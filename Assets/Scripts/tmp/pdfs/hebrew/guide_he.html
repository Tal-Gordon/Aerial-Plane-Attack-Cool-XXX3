1. הפרויקט בעמוד אחד

נאום של 60 שניות
Aerial Plane Attack הוא סימולטור טיסה ולמידה ב־Unity 6. ארבעה סוגי AI - Fixed NeuroEvo, ‏NEAT, ‏PPO ו־SAC - שולטים באותה פיזיקת מטוס ומבצעים אותן משימות. הארכיטקטורה מפרידה בין הסימולציה המשותפת למחזור החיים של הלמידה, כדי להשוות בין האלגוריתמים בלי לשכפל את המטוס או את היעדים.

חמש העובדות החשובות

  • שני יעדי אימון ממומשים: Max Altitude ו־Flight School. ל־Dogfight קיימים מצלמה, בחירה ונשק, אך אין יעד קרבי או חיישן קרב.
  • סביבה משותפת אחת: חיישנים מייצרים תצפיות; בקר מייצר pitch, roll, yaw, throttle; ‏JetPhysics מזיז את אותו מטוס; והיעד מעניק ציון ומחליט מתי הריצה מסתיימת.
  • שתי משפחות אימון: השיטות האבולוציוניות מריצות את המוחות ואת האבולוציה בתוך Unity; ‏PPO/SAC משתמשים ב־ML-Agents ובמאמן Python חיצוני.
  • ההפשטה המרכזית: SimulationManager מרכיב את הריצה; Paradigm מנהל את מחזור האימון; ו־Engine מנהל אבולוציית אוכלוסייה. ל־RL אין IEvolutionEngine.
  • רציפות ניסויים: ההגדרות והשמירות מזוהות לפי (track scene, AI type), ולכן שני מסלולי Flight School אינם דורסים זה את זה.

תשובת פתיחה טובה

"הפרויקט הוא קודם כול פלטפורמת ניסויים, ולא רק משחק טיסה. ההחלטה הארכיטקטונית החשובה היא שכל שיטות ה־AI חולקות את אותם חיישנים, פעולות, פיזיקה וחוזי יעד. SimulationManager מרכיב את הריצה, ITrainingParadigm מסתיר את ההבדל בין דורות לפרקים, ו־IEvolutionEngine מפריד בין שני האלגוריתמים האבולוציוניים."

4. מה משתנה בין ארבעת סוגי ה־AI

היכן מתרחשת הלמידהגבול האימוןייצוג המדיניותסוג AI
בתוך Unity: ‏ClassicNeuroEvoEngine.מחכים לכל האוכלוסייה ואז מפתחים דור חדש.רשת צפופה בעלת מבנה שכבות קבוע.Fixed NeuroEvo
בתוך Unity: ‏NeatEngine + SharpNEAT.מחכים לאוכלוסייה, מצמידים fitness ומקדמים דור.גנומים שמפתחים משקלים וטופולוגיה ומפוענחים ל־NeatBrain.NEAT
תהליך Python חיצוני.מטוסים מסיימים פרקים עצמאית; המאמן מעדכן מדיניות משותפת.מדיניות ומצב optimizer של ML-Agents.PPO
תהליך Python חיצוני.פרקים עצמאיים ועדכוני מאמן off-policy.מצב actor/critic והתנהגות replay של ML-Agents.SAC

המשפחה האבולוציונית

  • אצווה סינכרונית: מטוס סופי מקבל fitness סופי ומושבת; האבולוציה מחכה עד ש־aliveCount מגיע לאפס.
  • טופולוגיה קבועה: הטובים נשמרים באליטיזם; שאר המוחות נוצרים מבחירת טורניר ומוטציה.
  • NEAT: ‏SharpNEAT מטפל במינים ובאבולוציה מבנית. ציונים שליליים מוזזים כלפי מעלה משום שהספרייה דורשת fitness לא־שלילי.

משפחת למידת החיזוק

  • פרקים עצמאיים: JetMLAgent מקבל פעולה, מפעיל אותה, מבקש תגמול מהיעד ומסיים את הפרק שלו כשמגיעים למצב סופי.
  • בעלות חיצונית: RLParadigm כותב YAML, מפעיל mlagents-learn, מגדיר BehaviorParameters ו־DecisionRequester, ומנהל resume/כיבוי.
  • אין אובייקט IBrain: ‏GetChampionBrain מחזיר null עבור PPO/SAC. ה־UI יכול לראות קלטים ופעולות אחרונות, לא את משקלי המאמן.

טענת ההוגנות - והגבול שלה

מה ניתן לטעון
ממשק הסביבה משותף, ולכן ההשוואה שולטת במשתני מימוש רבים. עם זאת, דורות אבולוציוניים ופרקי RL משתמשים במשטרי דגימה ועדכון שונים; זמן קיר זהה או מספר פרקים זהה אינם בהכרח תקציב ניסויי זהה.

תשובת השוואה שימושית

למה לא מחלקת AI ענקית אחת? מפני שלאבולוציה מבוססת דורות ול־RL עם פרקים עצמאיים אין לולאה טבעית משותפת. הממשק מאחד רק את מחזור החיים שהאפליקציה באמת צריכה: initialize, tick, snapshot, persistence, inference ו־dispose.

5. SimulationManager: הרכבה וניתוב

משפט לזיכרון
המנהל מחליט מה קיים ולאן הקריאות נשלחות; הוא אינו מבצע את הלמידה.

רצף האתחול ב־Start()

1
להמיר את objectiveProvider של הסצנה ל־IObjective ולעצור אם הסצנה אינה מוגדרת נכון.
2
לטעון הגדרות למסלול הפעיל; אם נבחר סוג AI אחר בתפריט, להשתמש בברירות המחדל המתאימות.
3
ליצור את האוכלוסייה, להפעיל בדיוק את החיישן שהיעד דורש, ולהפיק ממנו את רוחב הקלט של המודל.
4
ליצור שירותי כוונון לתגמולים, hyperparameters וצורת הרשת.
5
למפות AIType ל־Paradigm הנכון ולאתחל אותו עם האוכלוסייה, ההגדרות והיעד.
6
אופציונלית, לטעון ריצה שמורה או להיכנס למצב challenge שהתפריט ביקש.
Managers/SimulationManager.cs - ניתוב ה־tick המרכזי
private void FixedUpdate()
{
    if (inChallengeMode) { TickChallenge(); return; }
    if (inInferenceMode)
    {
        activeParadigm?.TickInference();
        return;
    }
    activeParadigm?.Tick();
}
Managers/SimulationManager.cs - מיפוי סוג AI למחזור חיים
private ITrainingParadigm CreateParadigm(AIType type)
{
    switch (type)
    {
        case AIType.FixedNeuroEvo:
            return new EvolutionaryParadigm(new ClassicNeuroEvoEngine());
        case AIType.NEAT:
            return new EvolutionaryParadigm(new NeatEngine());
        case AIType.PPO_MLAgents:
        case AIType.SAC_MLAgents:
            return new RLParadigm();
        default:
            return null;
    }
}

מה לציין בקוד

  • זוהי הזרקת תלות דרך constructor: אותו EvolutionaryParadigm מקבל אחד משני Engines.
  • PPO ו־SAC חולקים RLParadigm; סוג ה־AI משנה את ה־YAML וההגדרות.
  • המנהל מפעיל בכל FixedUpdate מחזור חיים אחד בלבד: training, inference או challenge.

6. ITrainingParadigm: הסתרת הבדלי מחזור החיים

זהו Strategy הפונה אל שכבת האפליקציה. המנהל יכול לאתחל, לבצע tick, לקרוא telemetry, לשמור/לטעון, להיכנס ל־inference ולנקות משאבים בלי לדעת אם האלגוריתם רץ באצוות C# או בפרקים דרך Python.

EvolutionaryParadigm מנהל דור

5. spawn מחדששיוך מוחות חדשים
4. אבולוציהכאשר aliveCount == 0
3. הוצאהסיום מטוסים terminal
2. הערכהתגמול לכל מטוס חי
1. שיוךה־engine יוצר מוחות
  • במהלך ההערכה: CurrentFitness += GetStepReward(). בסיום: CalculateTotalFitness(), השבתה והקטנת aliveCount.
  • בגבול הדור: איסוף ציונים, קריאה ל־EvolveNextGeneration(), עדכון סטטיסטיקה, שיוך מוחות ו־spawn מחדש.

RLParadigm מנהל את מחזור המאמן

  • Initialize אינו מפעיל Python. ה־Tick הראשון מתחיל ריצה חדשה; LoadState יכול להכין checkpoint ולהתחיל ישירות ב־resume.
  • BehaviorParameters מוגדר לפני הוספה/הפעלה של JetMLAgent, כדי למנוע רישום עם ברירת מחדל של אפס פעולות.
  • JetMLAgent, ולא RLParadigm.Tick, מנהל את לולאת הפעולה-תגמול-סיום. ה־Paradigm מנהל תהליך, סטטיסטיקה, persistence, Academy וניקוי.
הסבר תכנוני טוב
הממשק אינו מעמיד פנים שהלולאות זהות. הוא מאחד רק את מה ששאר האפליקציה באמת צריכה. זהו Strategy ברמת מחזור החיים של האימון.

  • יוצר NeuroEvoBrain צפוף אחד לכל מקום באוכלוסייה לפי מבנה הרשת.
  • ממיין זוגות מוח/ציון, מעדכן אלוף היסטורי ושומר לפחות את האחוז העליון כ־elites.
  • לכל ילד שאינו elite מבצע טורניר של חמישה מועמדים, מעתיק את המנצח ומבצע מוטציה.
  • קורא הורים מ־parentPool בלתי משתנה, כדי שילדים שכבר נכתבו לא יהפכו בטעות להורים.
  • CaptureState שומר shape, כל המוחות השטוחים, אלוף, ציון ודור ב־JSON.

NeatEngine

  • בונה את מפעל הגנומים, decoder, speciation ואת אלגוריתם האבולוציה של SharpNEAT.
  • מצמיד ציונים לאובייקטי הגנום הנוכחיים לפני StepOneGeneration, משום שהספרייה בונה ומסדרת מחדש את הרשימה.
  • מזיז ציונים שליליים ומוסיף baseline כך שכל ערכי ה־fitness חיוביים.
  • מגן על שני האחוזים העליונים מפני אובדן elite הסתברותי ומאתר מחדש את מקום המנצח לצורך המצלמה.
  • CaptureState שומר XML מלא של האוכלוסייה ושל האלוף בתוך payload JSON אטום.
למה מצב אטום חשוב
EvolutionaryParadigm אינו יודע אם המוח הוא משקלים שטוחים או גנום SharpNEAT. הוא שומר רק את מחרוזת EngineState, ופרטי הסריאליזציה נשארים ב־engine שבבעלותו.

היכן ההפשטה אינה מושלמת

IEvolvableBrain חושף Copy ו־Mutate, דבר שמתאים לטופולוגיה קבועה אך לא ל־NEAT, שבו הפעולות שייכות לגנום/engine. פיצול נקי יותר יפריד בין phenotype שמסוגל לבצע inference לבין מוח fixed-topology שניתן לשנות ישירות.

8. שתי עקיבות מקצה לקצה

עקיבה א': דור אחד של Fixed NeuroEvo

  1. SimulationManager יוצר EvolutionaryParadigm(new ClassicNeuroEvoEngine()).
  2. Initialize מבקש מוחות מה־engine, משייך מוח לכל JetAgent, מגדיר cadence וקורא ל־SetStartingState.
  3. JetAgent קורא מדי כמה ticks את החיישן, מעביר תצפיות ל־Brain.GetControlOutputs ומשתמש באותה פעולה בין החלטות.
  4. JetPhysics משלב דחף, עילוי, גרר, מומנט, damping ויציבות בכל צעד פיזיקה.
  5. EvolutionaryParadigm צובר תגמול. מטוס terminal מקבל fitness סופי ומושבת.
  6. כשכל המטוסים הסתיימו, ה־engine מקבל ציונים, מחזיר מוחות שהתפתחו, וה־Paradigm יוצר את הדור הבא.

עקיבה ב': פרק אחד של PPO/SAC

  1. SimulationManager יוצר RLParadigm. ה־Tick הראשון כותב YAML ומפעיל mlagents-learn, אלא אם זה מסלול resume/inference.
  2. RLParadigm מגדיר BehaviorParameters ו־DecisionRequester, ומזריק הפניות ל־JetMLAgent.
  3. CollectObservations מעתיק את וקטור החיישן אל ML-Agents.
  4. מדיניות Python מחזירה פעולות רציפות; JetMLAgent מפעיל אותן על אותו JetPhysics.
  5. JetMLAgent מבקש תגמול מאותו IObjective, קורא ל־AddReward ומסיים את הפרק במצב terminal.
  6. OnEpisodeBegin מדווח את הציון הקודם, מאפס את המטוס ומבקש מצב התחלה חדש.
אם שואלים היכן מתרחשת הלמידה
Fixed/NEAT: ‏Unity C# engine מחזיר אוכלוסייה חדשה.
PPO/SAC: ‏Python מעדכן מדיניות משותפת מטרג'קטוריות שנשלחו דרך ML-Agents; ‏Unity היא הסביבה.

Inference

  • אבולוציה: טעינת IBrain של האלוף למטוס יחיד והרצת היעד בלולאה בלי אבולוציה.
  • RL: הכנת checkpoint והפעלת mlagents-learn --resume --inference. המדיניות קפואה, אך עדיין דרושים Python ו־Academy.

כוונון בזמן ריצה

  • Hot: שינוי תגמול או scalar תואם משתמש ב־Save -> Load מוגן, כך שהמצב הנלמד נשמר. גיבוי מונע דריסה של השמירה הידנית.
  • Cold: שינוי גודל אוכלוסייה או ארכיטקטורת רשת אינו תואם למשקלים הישנים. שומרים הגדרות ובונים מחדש מאפס; השמירה הידנית נשארת.

אתגר מול מדיניות שמורה

המנהל הנוכחי תומך גם במרוץ Flight School בין מטוס אנושי ל־AI שמור וקפוא. הוא טוען את ההגדרות והיעד השמורים, מפעיל inference עבור ה־AI, יוצר עותק אנושי, מבטל נשק והתנגשויות הדדיות, משתמש באותו קו זינוק ומדרג לפי מספר חישוקים ולאחר מכן מהירות ממוצעת. אין למידה ואין שמירה.

הסתייגות שמירת RL
כפתור Save יכול להעתיק רק את ה־checkpoint האחרון שהמאמן כתב. התקדמות מאז אותו checkpoint אינה נשמרת, ולכן זו שמירה מוגבלת checkpoint ולא snapshot מדויק של הפריים הנוכחי.

10. סיפור הדגמה נקי לבוחנים

רצף מומלץ בהדגמה

  1. בחר מסלול וסוג AI. הסבר שהבחירה נשמרת ב־GameSession, ושהיעד בסצנה קובע את החיישן ואת חוזה התגמול.
  2. הצג כמה מטוסים באימון. ציין שהאוכלוסייה והפיזיקה משותפות לכל האלגוריתמים.
  3. פתח telemetry. הסבר generation לעומת episode, ‏max/average נוכחיים מול best היסטורי, בחירת מטוס ומגבלות visualizer ב־RL.
  4. בחר מטוס. חבר בין ההתנהגות, התצפיות, הפעולות ופירוט התגמול.
  5. הצג save/load או inference. הסבר את ההבדל בין מצב אימון מלא לבין replay של מדיניות אחת.
  6. אם יציב, הצג tuning או challenge. השתמש בו כדי להסביר hot/cold או הערכת מדיניות קפואה.
